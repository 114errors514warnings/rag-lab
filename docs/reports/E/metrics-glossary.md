# E 线指标词典（metrics glossary）

> 所有 E 阶段报告共用本词典。报告里出现的每个指标名都对应这里的一行（含义 / 计算口径 / 常见标准）。
> 口径来源：`rag_eval/evidence.py`（证据匹配与覆盖）、`rag_eval/metrics.py`（指标口径）、`rag_lab/scoring.py`（聚合）。
> **改口径必须 bump `EVAL_VERSION`**（当前 `v2`）。

## 0. 判定语义（报告里"标准"列怎么写）

| 字段 | 含义 | 例 |
|---|---|---|
| `max` | **绝对上限**，不依赖基线 | `p95_latency_ms ≤ 2000`、`leakage_rate = 0` |
| `min_delta` | 相对基线**至少要提升**多少 | `mrr@5 ≥ 基线 + 0.10` |
| `max_delta` | 允许的**最大回退**（写负数或 0，如 `-0.01`） | `recall@5` 回退 ≤ 0.01 |

判定取值：`PASS` / `FAIL` / `BASELINE`（缺基线，无法算 Δ）/ `NO_GATE`（该阶段未给此指标设门禁，仅观察）。
**运行器退出码：任一 `FAIL` → 1，否则 0。**

## 1. 检索指标（判据单位 = 证据：文件 + 行区间 / symbol）

- **"匹配"**：检索单元与证据**同文件**，且行区间相交（或 symbol 相同）。
- **"充分证据集"**：题目要求的最小证据集合；一个题目可有多组**等价**充分集，命中任一即可。

| 指标 | 中文名 | 它衡量什么 | 计算口径 | 常见标准 |
|---|---|---|---|---|
| `recall@k` | 覆盖式召回 | 证据是否被**检索**捞到：**至少一组充分证据全部落入检索 top-k** 的题数 ÷ 可答题数 | 二值（覆盖=1/未覆盖=0）后取均值 | 相对基线回退 ≤ 0.01，或需提升 |
| `precision@k` | 检索精度 | 检索 top-k 里**命中证据**的单元占比 | 命中单元数 ÷ k，取均值 | 观察项居多 |
| `mrr@k` | 平均倒数排名 | 首个命中证据排得多靠前 | 1 ÷ 首个命中的名次（无命中记 0），取均值 | 回退 ≤ 0.01 / 需提升 |
| `ndcg@k` | 排序质量 | 按相关度等级（0/1/2）加权的排序好坏 | DCG@k ÷ IDCG@k（每条证据只计一次），取均值 | 回退 ≤ 0.01 / 需提升 |
| `context_evidence_coverage` | 上下文证据覆盖 | 证据是否被**最终送进生成**的上下文覆盖 | 口径同 `recall@k`，但算在 `context`（可能已扩展/裁剪）上 | 相对基线回退 ≤ 0.01 |

> 区别：`recall@k` 看**检索结果** top-k；`context_evidence_coverage` 看**送进 LLM 的上下文**。
> 二者分离是 E08（上下文扩展）能"召回不变、覆盖提升"的原因。

## 2. 生成 / 引用指标

| 指标 | 中文名 | 它衡量什么 | 计算口径 | 常见标准 |
|---|---|---|---|---|
| `answer_accuracy` | 答案准确率（rubric 代理） | 可答题"召回覆盖 **且** 有引用"；无答案题"正确拒答" | 逐题 0/1 后取均值（含无答案题） | 相对基线降幅 ≤ 0.02 |
| `citation_support` | 引用支撑度 | 回答引用中**命中证据**的比例（防"只凭流畅度"） | \|引用∩证据\| ÷ \|引用\|；无引用记 0 | 观察项 |
| `no_answer_accuracy` | 拒答准确率 | 无答案题是否被**正确拒答** | 正确拒答题数 ÷ 无答案题数 | 不得下降（基线常为 0→1.0） |

## 3. 安全指标

| 指标 | 中文名 | 它衡量什么 | 计算口径 | 常见标准 |
|---|---|---|---|---|
| `leakage_rate` | 跨项目混入率 | 检索结果里**不属于该题所属项目**的块所占比例（"串味"） | 逐题 foreign÷retrieved（仅统计有 `project_id` 的题），取均值 | **必须 = 0** |

## 4. 成本 / 性能

| 指标 | 它衡量什么 | 计算口径 | 常见标准 |
|---|---|---|---|
| `avg_latency_ms` | 平均端到端耗时 | 逐题耗时取均值 | 观察项 |
| `p95_latency_ms` | 第 95 百分位耗时（含网络） | 逐题耗时的 p95 | 绝对上限（如 ≤4000） |
| `avg_prompt_tokens` | 送进生成的上下文平均 token | 逐题 prompt token 取均值 | Token 预算上限（如 ≤2000） |
| `avg_completion_tokens` | 生成内容平均 token | 逐题 completion token 取均值 | 观察项 |
| `cost_per_query_usd` | 单查询成本 | 逐题成本取均值（免费模型=0） | 上限（如 ≤$0.005） |

## 5. 聚合维度

| 形式 | 含义 |
|---|---|
| `<指标>` | **微平均**（按题量平均） |
| `macro_<指标>` | **宏平均**：先按题型求均值，再对各题型均值取平均（防某题型占比大而掩盖小题型） |
| `<指标>[<题型>]` | 分组值，题型 ∈ `symbol` / `semantic` / `dependency` / `literal` / `no_answer` / `update` |
| `n_answerable` / `n_no_answer` | 可答题 / 无答案题数量（分母口径） |

## 6. 数据集与证据粒度（重要）

- 用例字段：`case_id`（`QA`=proj-auth / `QB`=proj-sched / `QD`=文档题）、`query_type`、`gold_evidence`（文件 + 行区间 + symbol）、`split`。
- 评测**把 chunk 映射回源文件行区间/symbol**再判定，**不以 chunk_id 为唯一标准**。
- Golden 由人工种子标注（`adjudication.reviewed=false` 表示待复核）。

## 7. 与 S 线（旧七阶段）评测的区别

| | S 线 | E 线（本词典） |
|---|---|---|
| 数据 | `data/eval_suites/*.jsonl`（chunk_id 制） | `data/golden/cases.jsonl`（证据制） |
| 运行器 | `rag_eval/runner.py` | `scripts/run_eval.py` |
| 判据 | 阶段门禁 + `baselines/` | 预声明 `gates` + 配对 bootstrap CI |

> 两套并存；E 线报告里的指标**一律以本词典为准**。
