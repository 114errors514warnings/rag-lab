# E 线负结论裁决（2026-11-11）

> 背景：E03 / E05 / E06b / E07 未过门禁。本文件决定每一阶段是**接受负结论**、
> **改口径**，还是**换套件重测**——并写明什么条件下应该重测。

## 1. 裁决表

| 阶段 | 原结论 | 证据（来自原报告） | 裁决 | 理由 |
|---|---|---|---|---|
| **E03** 符号切块 | 未通过 | `recall@5` 0.8519 → **0.5926**；`mrr@5` 0.7914 → **0.6698**；模块级未覆盖行最高 **33/63** | **接受负结论** | 两个指标同时下降，且根因是结构性的（符号块丢失 imports / 常量 / 模块级语句）。换指标救不回来。 |
| **E05** 检索模式 | Dense 最优 | recall：Dense 0.963 / BM25 **0.7778** / Hybrid 0.9259；**MRR：BM25 0.7883 > Dense 0.7833**；precision：BM25 0.4414 > 0.3333；Hybrid 的 recall 差 −0.037，95% CI 含 0 | **改口径** | 不能说"BM25/Hybrid 无用"，只能说"**在覆盖式 recall@5 口径下无增益**"。BM25 在排序质量（MRR）、精确率、延迟上各有优势；Hybrid 的差异**不显著**。 |
| **E06b** Rerank 模型对照 | 未通过 | Qwen3-Reranker-4B 的 `mrr` 更高，但**拒答**未过 | **部分接受** | rerank 质量本身更好；失败点在**拒答阈值**（E06 的口径），不是模型能力。 |
| **E07** Query Rewrite | 无增益 | 召回已饱和（0.963），改写后再无提升 | **接受负结论 + 标注饱和** | 在接近上限的套件上无法观测增益；这不是"改写没用"的普适结论。 |

## 2. 对上层结论的影响

- **"模型 > 链路"不变**：E04（换 bge-m3，recall 0.8519 → 0.963）与 E06（rerank，mrr +0.0895）都是正向。
- **"混合检索无增益"必须限定范围**：本套件（111 chunks 量级）+ 覆盖式 `recall@5`。
- **E03 的负结论是"符号块单独用不行"**，不等于"符号信息无用"——E03 已有 `symbol_union`（定长 + 符号并集），
  可作为"要符号定位时"的备选，但**尚未在 L2 验证**。

## 3. 什么条件下重测（触发条件，不是"以后再说"）

| 阶段 | 触发条件 | 重测方式 |
|---|---|---|
| E03 | 出现"按符号精确跳转"的刚需（IDE / 代码问答） | 用 `chunking: symbol_union` 重跑，比较"模块级覆盖率"与 recall |
| E05 | 语料 > 1000 chunks，或查询以自然语言为主 | 重跑三模式；以 **nDCG/MRR** 为主指标，recall 作辅助 |
| E06b | 重新标定拒答阈值（用 no-answer 分布） | 同 E06 套件，只换 rerank 模型 |
| E07 | 换"召回未饱和"的套件（recall@5 < 0.85） | 同 E07 配置，换数据集 |

## 4. 一句话

> **E03/E07 接受负结论；E05 改口径（覆盖式召回无增益 ≠ 检索无用）；E06b 部分接受（失败在拒答不在模型）。**
> 四条都写清了"什么条件下重测"，避免变成无限期搁置。
