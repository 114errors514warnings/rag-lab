# E10 阶段报告 · 增量索引（vs 全量重建）

- 实验：E10（E 计划，R3）
- 状态：✅ **机制验证通过**（复用 S2 的 `IncrementalIndexer`，未新造）
- 日期：2026-10-15
- 度量脚本：`scripts/exp_e10_incremental.py`（离线 hashing，确定性、无网络）
- 架构说明：[`stage-E10-architecture.md`](stage-E10-architecture.md)

## 1. 目标与主变量
**主变量**：索引维护方式（全量重建 → 增量更新）。验证"改动 1 个文档时，**只重建受影响的切片**，其余向量逐字节不变"。

## 2. 方法
- **L1**：`python -m pytest -q` → **108 passed**（含 S2 的 `tests/test_incremental_index.py`：只重建受影响切片、增删改、状态持久化）。
- **基准**：`python scripts/exp_e10_incremental.py`（真实语料 `data/kb`，10 文件）。

## 3. 结果

| 方式 | 重建块数 | 耗时(s) | 说明 |
|---|---|---|---|
| 全量重建 | **111** | 0.031 | 10 个文档全量切块 + 嵌入 |
| 增量（改 1 个文档 `proj-auth/auth.py`） | **7** | 0.001 | changed 1 / reused 9 |

- 未被改动的 **104 块向量：逐字节不变**（`unaffected_vectors_byte_identical = true`）。
- 脚本退出码 **0**（断言成立）。

## 4. 结论
改 1 个文档 → **只重建 7 / 111 块（−94%）**，其余向量逐字节不变 → **"只重建受影响切片"成立**。
对应真实项目：Embedding API 的调用量按同比例下降（成本/时间节省与改动范围成正比）。

## 5. 边界与不做
- 用**离线 hashing** 度量（确定性）；耗时反映本地计算，"重建块数"是真实 API Embedding 成本的代理。
- **L2 `recall` 不适用**：增量不改检索，且选项 B 下无基线；故以机制（L1 + 基准）为准。
- 当前是**全量 diff**（按 `doc_id` 指纹），**非文件系统事件监听**；文件监听属后续工程项。
- 未涉及"删除残留 / 孤儿块"之外的安全回归（见 E11）。
