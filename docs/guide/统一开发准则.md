# 实践项目合集 · 统一开发准则

> 适用范围：本目录内所有**学习实践项目**（当前：`rag-lab`、`agent-runtime`；后续并入者同样适用）。
> 本文件是相关项目的**统一约束**；各项目自身文档（`docs/guide/`）在不冲突时继续有效。

## 一、汇报规范

1. **每次汇报的第一句话必须给出最直观的结论**（一句话），例如：
   - `E00 测试未通过：recall@5 0.8148 → 0.7407（基线不复现）。`
   - `S4 测试通过：citation_precision Δ=0，avg_prompt_tokens=260.4 ≤ 2000。`
   结论之后才是细节、证据与建议。

## 二、版本与文档修改规范（**只增不改**）

2. **需要修改"之前版本"的内容时**（代码、配置、口径、基线等）：
   - 在**该历史版本对应的报告**末尾**追加**一章「后续变更」，写明：**修改时间、触发原因、改了什么、复测结果**；
   - **绝不修改报告原有的任何内容**（正文、表格、结论一律保持原样）。
3. **架构说明同理**：在其末尾追加「后续变更」，并**给出修改后的完整架构说明**（整篇重述，标注修改时间），
   **不得改动原文**。
4. 历史报告 / 架构说明 / 数值基线一律**只追加、不改写**；新基线 = 新文件（文件名带阶段/系统/时间标识）。

## 三、阶段实现与测试流程

5. 每个阶段固定动作：**写模块 → L1（pytest，机制正确性）→ L2（阶段门禁，相对冻结基线的 Δ）→ 记录**；
   重要阶段另出 **Archify 架构图**（`validate/deliver/check/browser-check` 全通过）。
6. 每个阶段产出**两份独立文档**：**报告**（`...-report.md`）与**架构说明**（`...-architecture.md`）。
7. **测试未通过就先停下并汇报**（遵循第一条给出一句话结论）；定位原因、给出方案，等待决策后再继续。
8. 数据集与基线冻结：运行比对数据集 `sha256`；基线与历史报告**只读**。

## 四、关联集与评估口径

9. **关联集** = 本目录（`实践项目合集`）内的项目。**进度/完成度评估只看关联集**；
   实现过程中**可以借鉴其它无关项目**（如 ContextOptimizer / AI Drama / HIL），但那些**不计入关联集进度**。

## 五、目录与命名约定

10. 实验/阶段报告：`docs/reports/R{n}/stage-<阶段>-report.md`；架构说明：`...-architecture.md`；
    架构图：`docs/reports/R{n}/diagrams/` 或项目内 `.archify/<type>-<slug>-<时间戳>/`。
11. 每轮"不可变快照"记录：`docs/reports/R{n}/round-{n}.md`（沿用 rag-lab 既有约定）。
